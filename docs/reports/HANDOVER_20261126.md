# 二、核心方法论：三层评测体系

这是整个项目最关键的方法论，务必理解。

## 2.1 三层指标

| 层级 | 名称 | 定义 | 作用 |
|---|---|---|---|
| L1 | **数字 NRMS** | 纯浮点推理精度（无任何器件失真） | 网络拟合能力 |
| L2 | **器件 NRMS** | 经行为级模拟电路仿真后的精度 | **真正的目标** |
| L3 | **V_SAT 需求曲线** | 器件 NRMS 随 V_SAT 变化 | **工艺可行性** |

## 2.2 关键教训：不要只看「退化比」

早期我用 `退化比 = 器件NRMS / 数字NRMS` 排名，**这是错的**。原因：数字精度不同的模型，同样退化比对应的绝对器件精度差很远。

**正确做法：以绝对器件 NRMS 为唯一排名依据，退化比只作辅助参考。**

## 2.3 器件仿真模型（`analog_sim_generic.py`）

五个物理非理想项，按重要性排序：

| 项 | 参数 | 物理含义 | 实测影响 |
|---|---|---|---|
| **Gilbert cell 三次失真** | `V_SAT`, `BETA_H3` | tanh 非线性 + 三次项 | **决定性**，100% 退化来自此项 |
| 量化 | `BITS` | ADC/DAC 位宽 | 可忽略（8bit 足够） |
| 器件失配 | `SIGMA_MISMATCH` | 工艺偏差 | 可忽略 |
| 直流失调 | `SIGMA_OFFSET` | 运放失调 | 可忽略 |
| 热噪声 | `SNR_DB` | 电阻热噪声 | 可忽略 |

**Gilbert cell 数学模型**：
```
y = V_sat · tanh( w·x·(1 + β·x̂²) / V_sat )
```
其中 `β` 是三次失真系数（**实际默认 0.002**），`x̂` 是归一化输入。

> ⚠ **2026-11-27 更正**（`P2_ABLATE_20261127.md` §5）：此处曾写「默认 0.3」，与代码不符。
> `analog_sim_generic.P` 实际是 `BETA_H3=0.002`，且 `HETEROGENEOUS_RUN_2026-11-25.md`
> 的单因素诊断表以 β=0.002 实测出 NRMS 2.1482（失真爆炸），可证 0.002 才是真实口径。
> **另需注意**：β=0 在 `_gilbert` 里走 `return prod.sum(dim=2)`，会连同 tanh 削顶一起绕过，
> 所以「关三次失真」这个消融 case 实际关的是整套 Gilbert 非线性。

**与官方 PyTorch 前向的对齐精度：`max|diff| = 5.8e-07`（浮点噪声量级）** —— 这是可信度的基础。

### 默认仿真档位（V_SAT=16 的含义）
```python
V_SAT=16.0, BITS=6, BETA_H3=0.002, SIGMA_MISMATCH=0.01,
SIGMA_OFFSET=0.005, SNR_DB=70, MC=2 次平均（见 2026-11-27 更正：此行原写 BITS=8/β=0.3/σ_mm=0.02/SNR=60）
```
V_SAT=16 约等于「±16V 供电的模拟乘法器」，是**普通双极工艺可达到的水平**，非高压特殊工艺。

## 3.4 机理：通道加宽 = 信号能量分散（本阶段最重要的发现）

逐层幅度诊断对比：

| 模型 | head_in 累积 RMS | 器件 NRMS |
|---|---:|---:|
| L10-ch18 | 30.82 | 0.2785 |
| L10-ch24 | 16.43 | 0.1702 |
| L10-ch32 | 更低 | **0.1393（中位）** |

**关键洞察**：幅度下降只能解释一部分改善。真正的机理是：

> **信号能量被分散到更多通道，每个 Gilbert cell 承担的信号幅度更小，工作点更靠近 tanh 的线性区中心，进入三次失真区的样本比例大幅下降。**

这是**统计效应**：若信号能量均匀分散到 C 个通道，单通道幅度 ∝ 1/√C，进入非线性区的概率超线性下降。

精确一点说，决定幅度的是**每组有效通道数 `ch/g`**，单通道幅度 ∝ 1/√(ch/g)：
- 加宽（ch↑，g 不变）→ ch/g↑ → 幅度↓ → 失真降
- 加大分组（g↑）→ ch/g↓ → 幅度↑ → **失真升**（这就是 §4.7 失败的数学根据）

**物理意义**：相当于把一个大信号拆成多个小信号并行处理，每个乘法器都在自己的线性区工作。这在模拟电路里是**天然优势**——不需要提高供电电压，只需要更多（但每个更便宜的）乘法器。

**与「减层」的关系**：两者是独立机理，可叠加。
- 减层 = 减少失真源串联次数（head 累加链 15→10）
- 加宽 = 降低每个失真源的输入幅度
- L10-ch32 同时用了两者。

**这是全项目最重要的一张表，三个推论**：

1. **数字精度极度稳定（变异 2.4%）** → 拓扑表达力充足、训练充分，**不存在容量问题**
2. **器件精度极不稳定（变异 38.7%）** → 器件鲁棒性对训练轨迹高度敏感，**这是方案当前最大的工程风险**
3. **中位 0.1393 vs A2 的 0.6076 = 4.4×**；即使最差种子 s31 仍优 2.6×，**结论方向不变，但优势倍数大幅收窄**

**为什么会这样（推测，待验证）**：Gilbert cell 的失真强度是高度非线性的（三次项）。不同的随机初始化会导致权重分布不同，有的种子恰好把大部分权重的幅度落在 tanh 线性区，有的则推到饱和区。**这是一个「阈值效应」，所以方差极大。**

**含义**：下一步的 P0 不是继续加模型，而是**降低器件方差**。若能把变异压到 10% 以内（0.13±0.013），这个方案才能在量产意义上可信。三个候选方向见 §9.1。

# 四、已排除的方案（避免新对话重复踩坑）

## 4.1 官方 A2 的 Slimmable 死锁（重要副产物）

**发现**：官方 A2 slimmable 配置 `init_strategy: smallest_and_zeros` 存在**梯度死锁**。

三条独立证据：
1. 导出权重中 **14598/15686 严格为 0（93.1%）**
2. 梯度扫描：ratio ≥ 0.5 时总梯度**严格为浮点 0**
3. 逐层核查：46 个 12 维参数张量的大通道**全部为零（46/46）**

**根因**：
```python
_input_mixer: Conv1d(..., bias=False)   # ← 无 bias
```
`smallest_and_zeros` 把大通道 weight + bias 清零，而 input_mixer 无 bias → **大通道输入恒为 0 → 梯度恒为 0 → 永久死锁**。

**后果**：训练时约 50% 的步落在 12ch 档但梯度为 0，**空转一半算力**。

**解决**：改用官方另一策略 `channel_causal`。100ep 下精度从 0.1786 → **0.1187（改善 33.5%）**。
配置：`experiments/a2_official/cfg/model_a2_causal.json`

> 这是给 NAM 官方的一个潜在 bug 报告素材。

## 4.2 残差缩放 α —— 完全无效

**做法**：`y = y + α · layer1x1(z)`

**为什么无效**：官方 `_Layer.forward` 里：
```python
layer_output = self._layer1x1(layer_output)      # 残差支路
residual = x[...] + layer_output
head_output = post_activation                    # ← head 支路，不过 layer1x1
```
α 乘在 `layer1x1` 上**只压残差链**，head 累加（最终输出路径）完全不受影响。

**实测**：α=0.5 时残差 max 从 89.8 降到 1.35（降 66 倍），但 head_in 仍是 30.82（输入的 394 倍），**V_SAT 需求毫无改善**。300ep 训透后器件精度 0.5050，**比原始 0.4306 还差**（网络靠放大权重补偿）。

## 4.3 Layer Gain Taper γ —— 有效但被训练抵消

**做法**：在每层 activation 之后乘 γ_i（作用点正确，同时覆盖 residual 与 head）
配置：`cfg2/model_taper-*.json`，实现：`analog_scaled_wavenet.py`

**150ep 时看似神奇**：taper-e30 退化仅 4.7×（vs a-grp4 的 44.5×）

**300ep 训透后优势大幅缩水**：

| 训练量 | 数字 NRMS | 器件 NRMS | 退化 |
|---|---:|---:|---:|
| 150ep | 0.0706 | 0.3561 | 5.04× |
| 300ep s7 | 0.0624 | 0.3757 | 6.02× |
| 300ep s11 | 0.0629 | 0.5648 | 8.98× |

**根因**：训练越充分，网络越倾向用满幅度拟合，γ 被权重增长部分抵消。且**种子间方差极大**。

**结论**：不是主要方向。作为「叠加项」仍有待验证价值。

## 4.4 减小 RF —— 反向有害

| 模型 | RF | 器件 NRMS |
|---|---:|---:|
| a-grp4 | 5386 | 0.4306 |
| a-grp4-rf50 | 2686 | 0.5718 |

RF 减半后**变差 33%**。反直觉但机理清晰：RF 缩短后小 dilation 层变密集，相邻层信号相关性更强 → 累加相干 → 幅度更高。

## 4.5 减层 —— 有效（已融入最终方案）

15 层 → 10 层，器件 NRMS 从 0.4306 → 0.2785（改善 35%）。
机理：head 支路逐层累加（`head_in += z_i`），减少层数直接减少失真源串联次数。

## 4.6 其他尝试（均失败）

- **bottleneck（bn6）**：3715 参数，器件 1.0233，最差
- **depthwise**：a-dw-ch24 器件 0.3368（尚可），但窄 depthwise 精度崩溃
- **AGC 归一化**：更差
- **直接缩放已训权重**：幅度压住但精度崩到 0.81
- **加层到 12（L12-ch18）**：0.3032，不如 10 层，印证「减层」结论

## 4.7 加大分组降交叉开关成本 —— **失败**（本轮新增，重要）

**动机**：交叉开关规模是 `ch²/g`，加大 g 就能在不减通道的前提下省交叉开关。
若成立，就能拿到「和 A2 差不多成本 + 4 倍精度」的完美方案。

**做法**：L10-ch32-g16（交叉开关 1280→640，省一半）、L10-ch24-g8（1440→720），均 300ep。

**结果（s7，V_SAT=16）**：

| 配置 | ch | g | 交叉开关 | 参数 | 数字 NRMS | 器件 NRMS | 判定 |
|---|---:|---:|---:|---:|---:|---:|---|
| **L10-ch32-g8（基准）** | 32 | 8 | 1280 | 18945 | 0.0578 | **0.0894** | — |
| L10-ch32-g16 | 32 | 16 | 640 | 15105 | 0.0629 | **0.3092** | **恶化 3.5×** |
| L10-ch24-g8 | 24 | 8 | 720 | 10849 | 0.0651 | 0.2382 | 恶化 2.7× |

**机理（自洽的负面结论，不是噪声）**：

单通道信号幅度 ∝ 1/√(每组有效通道数) = 1/√(ch/g)。

- g8→g16 时，每组有效通道从 4 降到 2 → **单通道幅度升高 √2 = 41%**
- 而加宽方案的全部收益，正是靠「幅度低 → 落在 tanh 线性区」
- **g16 等于把加宽的机理自己抵消掉了**

数字精度只略降（0.0578→0.0629），说明这不是训练不足或容量问题，而是**纯粹的器件工作点问题**。

**结论：`ch²/g` 这条降成本杠杆正式关闭。** 要降成本只能从「减抽头」（当前 60 个）或「摊薄每层」下手。

**方法论价值**：这是本阶段第一个「机理预测 + 实测验证一致」的负面结论 —— 说明 §3.4 的 1/√(ch/g) 模型是对的，可以拿它做后续设计的先验。

## 5.5 后台启动的坑（重要，必读）

远程执行长命令会被 SIGTERM（exit 137）。**必须用以下方式**：
```bash
# 正确：写独立脚本 + setsid 彻底脱离
cat > /root/autodl-tmp/run_x.sh <<'EOS'
#!/bin/bash
cd /root/autodl-tmp
export PATH=/root/miniconda3/bin:$PATH
python ... > logs/x.log 2>&1
EOS
chmod +x /root/autodl-tmp/run_x.sh
setsid bash /root/autodl-tmp/run_x.sh < /dev/null > /dev/null 2>&1 & disown
```

**其他踩过的坑**：
- `pkill -9 -f train_seeded` 会杀掉自己（命令行含同串）→ 用 `pkill -9 -f '[t]rain_see'`
- 后台任务只 `nohup ... &` 不 `setsid`，SSH 断开时会死
- 大并发评测会 OOM → 逐个评测 + 显存保护等待
- **本次 n14 曾因启动脚本被 SIGTERM 中断而静默失败**（目录都没建），务必检查 `ls -d runs/nXX_*` 确认

**本轮新增的三个坑（都很隐蔽）**：

1. **`setsid bash xxx.sh & disown` 在 expect 通道下仍可能被杀**
   现象：返回 `exit 137 / SIGTERM`，但远端进程实际上没起来。
   **解法**：把启动命令也写进脚本文件，然后 `setsid bash launcher.sh < /dev/null > /dev/null 2>&1`，让 launcher 内部 `nohup`。

2. **清理目录前必须先杀进程，否则产生竞态**
   现象：`rm -rf runs/xxx` 后 checkpoint 被删，但训练进程还活着，报 `FileNotFoundError: .../epoch=0046....ckpt`。
   **解法**：严格按 `pkill -9` → `sleep 3` → 确认 `pgrep -c` 为 0 → 再 `rm -rf` 的顺序。

3. **重复启动会互相拖慢 GPU**
   现象：同一配置起了两组进程，GPU 96% 但每个 epoch 变慢近一倍，且日志里出现两组 epoch 进度。
   **解法**：启动前先 `pgrep -fc "[t]rain_seeded"`，非 0 就先清理。

4. **新机缺 `cfg2/` 导致静默失败（rc=0！）**
   现象：训练 6 秒退出，`rc=0`，日志里是 `FileNotFoundError: cfg2/model_xxx.json`。
   **解法**：`xargs` 的并行子 shell 掩盖了返回码，**必须查日志文件内容，不能只看 rc**。

# 八、物理成本模型（模拟电路视角）

这是判断「易实现」的核心依据。

## 8.1 成本排序（由贵到便宜）

| # | 项 | 复杂度 | 说明 |
|---|---|---|---|
| 1 | **延迟线抽头数** | O(L·K) | 每层每个 kernel 抽头一个，模拟延迟线占用面积最大 |
| 2 | **交叉开关规模** | O(ch²/g) | Gilbert cell 阵列，每个是乘法器 |
| 3 | **head 累加链深度** | O(L) | 逐层累加，每个加法器都有失真 |
| 4 | **MACs/sample** | O(L·ch²·K/g) | 决定功耗 |
| 5 | **参数量** | — | 电阻比/电容比，几乎零成本 |

## 8.2 各方案成本对照

| 方案 | 层数 | 通道 | 分组 | 交叉开关/层 | 总数 | MACs/sample | 抽头数 | 器件NRMS |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A2（官方） | 15 | 12 | 4 | 36 | 540 | 3240 | 90 | 0.6076 |
| a-grp4 | 15 | 12 | 4 | 36 | 540 | 3240 | 90 | 0.4306 |
| L10-ch18-g6 | 10 | 18 | 6 | 54 | 540 | 3240 | 60 | 0.2785 |
| L10-ch24-g4 | 10 | 24 | 4 | 144 | 1440 | 8640 | 60 | 0.1702 |
| **L10-ch32-g8** ⭐ | 10 | 32 | 8 | **128** | **1280** | **7680** | **60** | **0.1393（中位）** |

**关键权衡**：
- L10-ch32 的交叉开关是 A2 的 **2.37 倍**，MACs 是 **2.37 倍**
- 但延迟线抽头**减少 33%**（抽头是最贵的项）
- 器件精度提升 **4.4 倍**（中位口径）

**结论**：把成本从「深度方向」（抽头、累加链）转移到「宽度方向」（交叉开关），是这次的核心交易。而交叉开关的单价远低于精密延迟线抽头，**综合成本可能反而更低**——这一点需要与硬件实现方确认。

## 8.3 成本优化：`ch²/g` 路线已证伪

**原计划**：加大分组把交叉开关降下来（ch32-g16 → 640，只比 A2 多 18%）。

**实测结果**：失败。器件 NRMS 从 0.0894 恶化到 0.3092（3.5×）。

原因见 §4.7：加大 g 会让每组有效通道数 `ch/g` 变小，单通道幅度 ∝ 1/√(ch/g) 反而升高，把加宽的收益抵消。

**新方向（未验证）**：
| 方向 | 手段 | 代价 |
|---|---|---|
| 减抽头 | 去掉一半 dilation 重复（60→33） | RF 从 5411 缩短，可能变差（参考 §4.4 减 RF 有害） |
| L12 + ch24 | 摊薄每层负担 | 层数增加，已验证 L12 变差（0.3032） |

# 九、待办事项（新对话从这里开始）

> **优先级已因本轮结果重排**：原 P0「验证 ch32-g16 成本优化」和 P1「3 种子确认」都已完成，
> 结论分别是「失败」和「方差 38.7%」。**新 P0 是降低器件方差。**

## 9.1 第一优先级：降低器件方差（**当前最大风险**）

5 种子器件 NRMS 变异系数 **38.7%**，最好 0.0894 / 最差 0.2376。若不解决，换台机器重训可能拿到 0.24。

### 方向 A：训练时引入可微器件失真做正则（推荐先试）

`analog_sim_generic.py` 已有完整前向。**Gilbert cell 的 tanh 本身可微**，可以直接在训练损失里加一项「器件前向 vs 理想前向」的差距惩罚，逼网络主动把权重分布调整到线性区。

```python
# 伪代码思路
loss = esr(pred_ideal, target) + λ * esr(pred_device, pred_ideal.detach())
```
- 优点：从根源解决，让「低失真」成为训练目标而非运气
- 代价：前向变慢约 2 倍；需要调 λ
- 风险：可能牺牲数字精度（需监控）

### 方向 B：权重衰减 / 谱归一化

大权重直接决定 Gilbert cell 是否饱和。加 weight decay 或谱归一化限制每层 Lipschitz 常数，应能压缩方差。

- 最简单：直接在 `learn_a2_300ep.json` 里加 `weight_decay`
- 更严格：对每层 conv 做谱归一化
- 优点：实现成本极低，先试这个
- 预期：方差下降，但数字精度可能略降

### 方向 C：训练后逐层 rescale

把每层权重按增益向 head 方向压缩（等价于把幅度往输入侧推）。之前「直接缩放已训权重」失败（精度崩到 0.81），但那次是无差别缩放，**分层定向缩放**是不同的。

### 方向 D：多训几个种子，用「器件精度」做模型选择

**工程上最务实**：反正训练只要 12 分钟，训 5 个种子、挑器件精度最好的那个。虽然不优雅，但立刻可用。代价是 5 倍训练成本（可接受，模型极小）。

## 9.2 第二优先级：补全 V_SAT 曲线的中位口径

当前 §3.3 的 V_SAT 曲线只有 s7。需要 5 个种子 × 10 档 V_SAT = 50 次仿真（约 25 分钟）。

```bash
python vsat_sweep.py runs/sd_L10-ch32-bigRF_s7 runs/sd_..._s11 ... 
```
**判定**：中位口径下的曲线是否仍全面优于 A2。预计整体上移 1.5 倍左右，但优势结构应保持。

## 9.3 第三优先级：跨数据集验证（外部效度）

当前所有结论都基于 TSA15 单个音箱。这是**最大的外部效度风险**。

本地已有 Zenodo 数据集（`dataset_zenodo/`）：Marshall JVM410H、Mesa Boogie 550/MarkV 各通道、BigMuff、TS9、Klon Centaur、Blackstar HT1 等 20+。

```bash
# 需先转换格式（见 src/tools/convert_*.py）
python train_seeded.py cfg/data_<新数据集>.json cfg2/model_L10-ch32-bigRF.json \
  cfg/learn_a2_300ep.json runs/n16_<数据集>_ch32_s7 7 --no-show --no-plots
```
**判定**：优势是否在 3 个数据集上都成立。若只在 TSA15 成立，则可能是过拟合。

**建议选**：一个高增益（Mesa Boogie Burn）、一个低增益（Mesa Clean）、一个 fuzz（BigMuff），覆盖失真度跨度。

## 9.4 第四优先级

### ④ 成本优化改道
`ch²/g` 已死（§4.7）。可试：
- 减抽头：`[1,7,47,157,329]×2` → 去掉一半重复层，抽头 60→33，但 RF 缩短（注意 §4.4 减 RF 有害）
- L12+ch24：已验证 L12 变差，优先级低

### ⑤ 更激进的通道数
ch32 已带来中位 0.1393。继续加宽是否还有收益？
- `ch48-g12`、`ch64-g16`（保持 ch/g = 4）
- 注意：交叉开关会到 192/256 每层，总数 1920/2560，版图压力大

### ⑥ 与硬件实现方对齐成本假设
当前成本模型是理论推导。需确认：
- 交叉开关 vs 延迟线抽头的实际面积/功耗比
- 1280 个交叉开关是否单芯片可行
- g8 分组的实现复杂度（是否需要额外开关网络）

## 9.5 锦上添花

### ⑦ 给 NAM 官方提交 slimmable 死锁的 bug 报告
证据完整（三条独立证据链 + 根因 + 修复方案），见 `docs/reports/A2_SLIMMABLE_DEADLOCK.md`。

### ⑧ 训练更久（500~800ep）
当前 300ep 数字精度已到 0.058 的天花板（5 种子σ仅 0.0014），继续训练收益有限。**优先级低。**

### ⑨ 蒸馏 / 量化感知训练
在训练时就把器件非理想项纳入损失函数——**这与 9.1 方向 A 是同一件事**，合并处理。

# 十、经验教训（血泪清单）

## 10.1 关于实验设计

| 教训 | 说明 |
|---|---|
| **单种子不可信（已用血验证两次）** | a-grp4 两种子差 35%；**L10-ch32 五种子差 38.7%（0.0894 vs 0.2376）**。所有关键结论必须 ≥3 种子看中位 |
| **短训练会骗人** | taper 在 150ep 显示 4.7× 退化，300ep 变 6.0×。**筛选可以用 150ep，但结论必须 300ep** |
| **退化比会误导** | 必须看绝对器件 NRMS。精度基线不同时退化比毫无意义 |
| **单数据集不可信** | 当前只测了 TSA15，需要跨数据集验证 |
| **中间 ckpt 只能看趋势，不能下结论** | 111ep 的 ch24 能看出方向，但 22:00 版据此写的「3.9×」后来被 300ep 数据推翻 |
| **数字精度稳 ≠ 器件精度稳** | 数字 σ=0.0014（2.4%）而器件 σ=0.0626（38.7%）。前者是训练问题，后者是**器件工作点问题**，两者解耦 |

## 10.2 关于评测代码

**`analog_sim_generic.py` 前后修了 8 个 bug，每个都导致数据全废**：

| Bug | 症状 | 修复 |
|---|---|---|
| state_dict 键名带两层 `_net.` 前缀 | KeyError | 剥前缀 |
| `input_mixer` 输入用错（用了残差流） | 数值全错 | 应为 condition（原始 1 通道） |
| `input_mixer` groups 用错 | shape 报错 | 应为 1 而非 g_in |
| `out_length` 用错（含 head_rechannel -1） | 数值偏移 | 分层区分 |
| 残差对齐方式错 | 数值偏移 | `y[:, :, -lo.shape[2]:] + lo` |
| `head_scale` 乘的位置错 | 数值差 1 个量级 | 应在 `_head_rechannel` **之后** |
| **漏用 `residual_scale`** | V_SAT=4096 时 ESR=44（应为 0.005） | 补上 |
| **漏用 `layer_gains`** | NRMS=54.6（应为 0.07） | 补上 |

**核心教训：每次修改仿真脚本后，必须先跑一次「纯浮点模式」（V_SAT=1e9, BITS=64, β=0），确认与训练时的数字精度一致（误差 < 1e-3）。这是唯一可靠的 sanity check。**

## 10.3 关于工程操作

- 远程长命令会被 SIGTERM → 必须 `setsid` + 独立脚本
- `pkill -f xxx` 会杀掉自己 → 用 `[x]xx` 方括号技巧
- 后台启动后**必须验证**（`ls -d runs/nXX_*` + `pgrep -cf train_seeded`），不能只看 echo 输出
- 中转传输 86KB/s，机器间直连 600KB/s
- 并发 8 个进程是 4090 的甜点（GPU 96%，显存 6.7/24 GB）

## 10.4 关于判断修正（诚实记录）

本阶段我**至少四次做出过错误判断，后被数据推翻**：

1. **误判「α 残差缩放有效」** → 实际 head 路径不过 layer1x1，完全无效
2. **误判「taper 是突破性方案」** → 150ep 数据是欠训练假象，300ep 优势缩水到 13%
3. **误判「L10 减层无效」** → 用中间 ckpt 测得幅度更高，完整训练后实测退化最低
4. **误判「6.8× 是方案水平」** → 那是单种子 s7 的运气。5 种子中位 0.1393 = **4.4×**

**教训**：任何「机理上应该有效」的推断（1、2、3），和任何「单次实验数据好看」的推断（4），
都必须用**完整训练 + 多种子**的实测数据验证。

**唯一可靠的做法**：把「≥3 种子看中位」变成流程，而不是事后补救。
本轮就是因为我先报了 6.8×，用户拿去用了，才需要回头改三份文档。

# 十一、一句话总结

> **用「10 层 + 32 通道 + 大 RF」替代官方 A2 的「15 层 + 12 通道」，在普通 ±16V 工艺下达到器件精度中位 0.1393（5 种子），比 A2 的 0.6076 优 4.4 倍；而 A2 需要 ±128V 才能接近这个水平。代价是交叉开关数量增加 2.37 倍、延迟线抽头减少 33%。**
>
> **但器件精度方差极大（变异 38.7%，最好 0.0894 / 最差 0.2376）—— 这是当前最大风险，也是下一步的 P0。**
>
> **成本优化（加大分组 g）已证伪：g16 省一半交叉开关，但器件精度恶化 3.5 倍，因为分组抵消了加宽的机理。**
