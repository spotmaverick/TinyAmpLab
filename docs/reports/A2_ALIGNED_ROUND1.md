## 二、四条可靠结论

### 结论 1：分组卷积是决定性杠杆，且存在**最优点**

| 分组数 | 候选 | test NRMS |
|---:|---|---:|
| 1（全连接，=A2） | a2 | 0.1786 |
| 4 | a-grp4 | 0.0775 |
| 6 | a-grp6 | 0.0784 |
| 12（depthwise） | a-dw | 0.1117 |

**非单调**：1 组差、4~6 组最优、12 组又变差。

物理解释：`
- 全连接（1 组）：12×12 交叉开关，模拟里是 144 个乘法器/层，面积爆炸，但**精度也最差**——
  说明问题不在"混合不够"，而在**优化/容量分配**。
- depthwise（12 组）：完全切断通道间信息流，表达力不足 → 0.1117。
- 4~6 组：保留局部通道混合（每 2~3 个通道互相作用），交叉开关降到 1/4~1/6。
  **这在模拟里几乎免费**（只是把求和链分组），数字实现里却拿不到加速收益，
  所以官方没有动机用它。**这正是"模拟友好"与"数字最优"的分岔点。**

### 结论 2：A2 的 15685 权重严重冗余

`a-grp4` 用 **38% 参数、37% 交叉开关、25% 累加链深度**，拿到 **2.3 倍更低的 test NRMS**。
→ "A2 的参数量是必要的" 这一前提被直接推翻。

### 结论 3：延迟线可以减半，代价只有 9%

`a-grp4-rf50`：RF 5386 → 2686（延迟线抽头减半），test 0.0775 → 0.0844（**+8.9%**）。
→ 若延迟线是主要物理成本（模拟里确实如此），**这个 trade-off 极为划算**。
→ 但 kernel 缩短（`a-grp4-k3`，RF 2155）代价大得多（+72%），
   说明**"保 kernel、缩 dilation"优于"缩 kernel"**。

### 结论 4：val 到 test 无泛化间隙（这批架构的共性）

所有候选 val 与 test 差值都在 ±5% 以内（如 a-grp4: 0.0772 vs 0.0775）。
说明这批结果不是过拟合，**架构本身的泛化能力是真实的**。

## 四、必须诚实记录的两个问题

### 问题 1：A2 的 0.1786 与项目历史 A1 lite 的 0.0785 差 2.3 倍

已定位为**配置不同，不是评测错误**：

| | 历史 lite（A1 家族） | 本次 A2 Slimmable |
|---|---|---|
| 配置 | `OFFICIAL_ARCHS["lite"]` 两组 layer array | 官方 `wavenet_slimmable.json` **单组** |
| 通道/层 | 12→6 / 7+13 层 | 12 / 15 层 |
| kernel | 3 | **6** |
| 激活 | tanh（**门控**） | **LeakyReLU（无门控）** |
| RF | 4093（85.3ms） | 5386（112.2ms） |

按用户指示「A1 已过时，只对标 A2」，**0.1786 是正确的 A2 锚点**。
但仍需确认：A2 在 100ep 官方协议下是否就是 0.18 水平，还是需要更多训练。

### 问题 2：族 B（递归架构）当前精度远不够

`DiagSSM ch16`（305 参数、16 电容、**延迟线 = 0**）在 epoch 23 时 val ESR 0.387
（NRMS 0.62），与族 A 的 0.077 差 8 倍。
→ 递归结构在物理成本上碾压（无延迟线、参数少 20 倍），但**表达力严重不足**。
→ 需要规模化 + 结构化（多层、门控、更宽）才可能竞争。这是下一阶段的主攻方向。
