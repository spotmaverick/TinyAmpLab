# 资源规划与三机可用性结论（2026-11-26 晚）

> 背景：4090 今晚 23:00 关闭（按时计费），z100 / bw2 按任务计费。
> 目标：在有限窗口内最大化「对标官方 A2」的实验产出。

## 一、硬约束（实测，非推断）

| 机器 | Python | torch | 能跑官方 `nam` 0.13.0? | 结论 |
|---|---|---|---|---|
| **AutoDL 4090** | 3.12.3 | 2.8.0+cu128 | ✅ **可以**（已装 nam 0.13.0） | **唯一能跑官方框架的机器** |
| z100（8×Z100） | 系统 3.6.8 / anaconda3-2023.09 是 3.11.5 | DTK22 的 torch 1.10 **只编译了 py3.8** | ❌ 不行 | 不能跑官方包 |
| bw（单卡 BW） | 3.11 | 2.9.0+dtk | 未测（登录密码失效） | 待恢复 |
| bw2（89×8 BW） | — | 缺 gfx936 wheel | ❌ | 已确认阻塞 |

**根因**：官方 `nam` 0.13.0 要求 `python>=3.10`，而 z100 唯一可用的 torch（DTK22 自带）
是 py3.8 轮子。anaconda3/2023.09 虽是 py3.11，但没有配套的 torch（DTK 目录里没有 cp311 轮子）。

### 这意味着什么

「用官方模型权重 + 官方训练/推理代码」这个要求，**把可用的算力压缩到了 4090 一台**。
z100 的 8 卡、bw2 的 712 卡在这条路线上都用不上。

## 二、因此的资源策略

### 4090（主战场，23:00 前）
按价值排序：
1. **多种子复现最优候选**（已完成 `a-grp6-ch18` s7/s11/s23）
2. **族 A 剩余变体横扫**（成本低，5 秒/epoch）
3. **族 B2 递归架构**（延迟线归零的唯一希望，但慢：约 25 分钟/100ep）
4. 产物全部回传本地（不留算力机上）

### z100（备用，按任务计费）
- **不用于官方框架实验**（装不了）
- 可用于：优化后的自研架构大规模训练（不依赖 nam 包），
  或作为物理仿真的算力（`analog_sim` 只依赖 torch + 自定义代码）
- 当前队列空闲（7 节点有卡），但**先不投**——等 4090 的结果确定候选架构后再投，
  避免用 17GB 的小卡跑本可以在 4090 上快速迭代的实验

### bw / bw2
- bw 密码失效（`~/.ssh/bw_zzai.pass` 被拒），需用户重新提供
- bw2 仍缺 gfx936 wheel，且每核内存上限 3888MB
- **本轮不依赖这两台**

## 三、如果 4090 关闭后要继续

推荐把「自研架构 + 自研训练循环」搬到 z100：
- 已有 `train_a2.py` / `arch_search_v2.py` 等脚本是 py3.8 兼容的，可直接用
- 代价：失去官方包的直接可比性，需用相同的 esr 公式自行实现（口径已验证一致）

或者等 bw 密码恢复——bw 是**单卡 BW（64GB）**，torch 2.9 开箱可用，
是 4090 关闭后最合适的替代。
